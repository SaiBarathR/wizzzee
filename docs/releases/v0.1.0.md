# Wizzzee 0.1.0

> [!IMPORTANT]
> **Two bugs in this version give wrong answers without saying so.** Scanning a folder that is itself a symlink — `/tmp`, `/etc`, `/var`, or any `/private/…` spelling of them — reports zero bytes and zero files instead of the real total, alongside "Scan complete". And for a short window after deleting a file, the File View can reveal in Finder, or delete, a *different* file than the one clicked. Both are fixed in [0.2.3](https://github.com/SaiBarathR/wizzzee/releases/tag/v0.2.3); prefer it over this release.

The first public release. Wizzzee is a disk space analyzer for macOS in the
shape of [WizTree](https://diskanalyzer.com/): a folder tree with sizes, a list
of the biggest files, and a colored treemap you can click into.

It scans a full startup disk — around 3.9 million files — in roughly 15 seconds.

## What it does

- **Tree View** — the folder hierarchy with size, allocated size, item counts and
  modification dates. Sorting applies within each parent, so re-sorting by any
  column keeps the hierarchy intact.
- **File View** — the 1,000 biggest files anywhere in the scan, with a filter
  that searches names, or full paths when the query contains a `/`.
- **Treemap** — every file as a rectangle with area proportional to size, colored
  by extension and shaded so nesting depth is visible. Click to select,
  double-click a folder to zoom in.
- **Delete from the results** — Move to Trash or Delete Permanently from the
  context menu. Sizes update all the way up the tree immediately, with no
  rescan.
- **A headless CLI** — `--scan`, `--probe`, `--treemap`, `--uishot` and
  `--selftest` run the same engine without the interface. See
  [docs/cli.md](https://github.com/SaiBarathR/wizzzee/blob/main/docs/cli.md).

## Reading the numbers

- **On Disk is the default.** Logical size is misleading on macOS, where sparse
  container and VM images routinely report hundreds of gigabytes they do not
  occupy. Space on disk is what deleting something gives back.
- **Base-10 units,** matching Finder and Get Info. This differs from `df -h`,
  which is base-2.
- **Hard links are counted once,** with the amount that would otherwise have been
  double-counted shown in the status bar.
- **One volume per scan.** APFS firmlinks are followed once, so `/Users` is
  counted and `/System/Volumes/Data/Users` — the same directory by another path —
  is not.
- **Totals will not exactly match `df`.** Unreadable folders, APFS snapshots and
  filesystem metadata account for the difference; the header reports how many
  folders could not be read.

## Full Disk Access

Without it, macOS hides Mail, Messages, Safari, Time Machine and other users'
home folders, and the totals read low. The header says so when it detects this.

Grant it in **System Settings → Privacy & Security → Full Disk Access → +**,
adding `Wizzzee.app`.

Because the app is ad-hoc signed, macOS keys the grant to that exact binary, so
it has to be added again after installing a new version.

## Compatibility

- Requires macOS 14 or newer.
- Apple Silicon is verified.
- The universal app contains native `arm64` and `x86_64` slices. Intel hardware
  has not been tested, so Intel support is provisional rather than verified.

## Installation

1. Download `Wizzzee-0.1.0-macos-universal.zip` and `SHA256SUMS.txt`.
2. Keep both in the same directory and run `shasum -a 256 -c SHA256SUMS.txt`.
3. Unzip and move `Wizzzee.app` to Applications.
4. Open it once and dismiss the warning, then go to **System Settings → Privacy
   & Security** and click **Open Anyway** next to the message about Wizzzee.

Wizzzee is ad-hoc signed rather than Developer ID signed or notarized, so macOS
requires this one-time Gatekeeper confirmation. On macOS 14 you can instead
Control-click the app and choose **Open** — macOS 15 removed that shortcut for
apps that are not notarized.

## Verification

After extraction:

```sh
lipo -archs "Wizzzee.app/Contents/MacOS/Wizzzee"
codesign --verify --deep --strict --verbose=2 "Wizzzee.app"
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' "Wizzzee.app/Contents/Info.plist"
```

These should report both `arm64` and `x86_64`, a valid ad-hoc signature, and
version `0.1.0`.

You can also check the build itself:

```sh
"Wizzzee.app/Contents/MacOS/Wizzzee" --selftest
```

That builds a throwaway tree with known contents and verifies the scanner and
both delete paths against ground truth — 37 checks, no permissions needed.

## Known limitations

- Not notarized, so first launch needs the Gatekeeper confirmation above.
- One volume per scan; other disks and network shares are skipped.
- `/System`, `/usr`, `/bin` and `/sbin` live on the sealed system volume and
  cannot be deleted by anything, including an administrator. Wizzzee still shows
  them so the space is accounted for, and says so rather than failing with a bare
  permission error.
